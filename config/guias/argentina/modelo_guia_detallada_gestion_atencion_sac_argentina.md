# Modelo Guía Detallada Gestión Atención SAC Argentina

OBJETIVO
Establecer los lineamientos para la gestión y atención de consultas frecuentes de los usuarios de la operación Argentina, garantizando respuestas homogéneas, oportunas y alineadas con los procedimientos definidos para la operación.
ALCANCE
Aplica para todos los agentes encargados de la atención de usuarios de la operación argentina y contempla la gestión de consultas relacionadas con:
Inicio de jornada.
Seguimiento de errores de plataforma.
Validación de estados de pedidos.
Guías sin movimiento.
Visualización de productos.
Tiempos de entrega.
DEFINICIONES
Triage
Bandeja encargada de recibir y clasificar las consultas iniciales de los usuarios para su correcta gestión o escalamiento.
Guía
Documento logístico que permite realizar el seguimiento de un pedido durante todo su proceso de transporte y entrega.
Guía Sin Movimiento
Estado presentado cuando una guía no registra actualizaciones logísticas durante un período prolongado de tiempo y requiere validación o seguimiento adicional.
Error 500
Error técnico de plataforma que impide la correcta ejecución de una funcionalidad y puede requerir intervención del área de Desarrollo.
Desarrollo
Área encargada de gestionar errores técnicos, incidencias de plataforma y problemas relacionados con el funcionamiento del sistema.
RESPONSABLES
GUIA DETALLADA
5.1 INICIO DE JORNADA
La jornada inicia con el envío del reporte de gestión donde se informa el estado de las bandejas activas y los casos pendientes identificados al inicio del turno.
Procedimiento
Ingresar a la plataforma de gestión.
Validar las bandejas activas.
Contabilizar los casos pendientes.
Elaborar el reporte de inicio.
Compartir la información al equipo.
Categorías reportadas
Triage.
Comercial.
Administrativo.
Logística.
Garantías.
Soporte Técnico.
Total, General.
Consideraciones
Deben revisarse los pendientes del día anterior.
Los errores identificados deben documentarse para seguimiento.
El reporte debe enviarse al inicio de cada jornada.
5.2 GESTIÓN DE ERRORES DE PLATAFORMA
Cuando un usuario reporta un problema técnico que impide el uso normal de la plataforma, se debe solicitar evidencia para validar el comportamiento reportado.
Procedimiento
Solicitar un video donde se evidencie el error.
Revisar la información suministrada.
Identificar si se trata de un problema operativo o técnico.
Brindar orientación inicial al usuario.
Escalar cuando corresponda.
Consideraciones
El video debe permitir visualizar claramente la novedad.
Toda evidencia debe quedar registrada.
Los errores técnicos deben documentarse antes de escalarse.
5.2.1 Error 500
El Error 500 corresponde a una incidencia técnica que impide el correcto funcionamiento de la plataforma.
Procedimiento
Solicitar al usuario borrar caché.
Solicitar eliminar cookies.
Cerrar sesión.
Iniciar sesión nuevamente.
Realizar la validación desde un computador.
Verificar si el error persiste.
Solicitar evidencia fotográfica.
Escalar al área de Desarrollo cuando corresponda.
Escalamiento
Cuando el usuario confirme que realizó todas las validaciones y el error continúe presentándose, el caso deberá ser escalado al área de Desarrollo.
Consideraciones
Las validaciones iniciales son obligatorias.
Debe solicitarse evidencia antes de escalar el caso.
El área responsable del escalamiento es Desarrollo.
5.3 CONSULTA DE ESTADO DE PEDIDOS
Cuando un usuario solicita información relacionada con el estado de una orden, se debe validar la guía correspondiente para identificar la etapa actual del proceso logístico.
Procedimiento
Solicitar el número de guía.
Consultar el estado logístico.
Revisar los movimientos registrados.
Informar al usuario el resultado de la validación.
Consideraciones
Siempre debe solicitarse el número de guía.
La información debe validarse directamente en la plataforma.
La respuesta debe corresponder al estado actual del pedido.
5.4 GUÍAS SIN MOVIMIENTO
Las guías sin movimiento corresponden a pedidos que no presentan actualizaciones logísticas durante un período determinado y requieren seguimiento adicional.
Procedimiento
Solicitar el número de guía.
Validar la fecha del último movimiento.
Revisar el estado actual.
Escalar el caso a Francesca Leal cuando no existan movimientos recientes.
Informar al usuario el resultado de la gestión.
Consideraciones
Solo deben escalarse los casos que realmente no presenten movimiento.
Si la guía tiene actualizaciones recientes se debe informar al usuario.
Toda gestión debe quedar documentada.
5.5 VISUALIZACIÓN DE PRODUCTOS Y PEDIDOS ANTIGUOS
Cuando un usuario indica que no puede visualizar productos o pedidos antiguos, se debe explicar el funcionamiento de los filtros de la plataforma.
Procedimiento
Ingresar al módulo Mis Pedidos.
Seleccionar el botón de filtro.
Configurar el rango de fechas requerido.
Aplicar los filtros.
Consultar la información solicitada.
Consideraciones
La plataforma muestra por defecto los pedidos de los últimos siete días.
Los pedidos antiguos pueden consultarse utilizando los filtros disponibles.
El usuario debe seleccionar el rango de fechas correspondiente.
5.6 CONSULTA DE TIEMPOS DE ENTREGA
Los tiempos de entrega dependen directamente de la programación operativa de las transportadoras y pueden variar según la ubicación y las condiciones logísticas.
Procedimiento
Solicitar el número de orden.
Validar el estado actual del pedido.
Revisar si se encuentra dentro de los tiempos estimados.
Informar al usuario el resultado de la validación.
Consideraciones
Las transportadoras administran sus propias rutas de entrega.
No deben prometerse fechas exactas de entrega.
Se recomienda al usuario realizar seguimiento constante de la guía.
El usuario debe estar atento a llamadas o mensajes de la transportadora.
