# Modelo Guía Detallada SAC Triage México

OBJETIVO
Establecer los lineamientos para la atención y gestión de consultas frecuentes realizadas por los usuarios de la operación México, garantizando respuestas homogéneas, oportunas y alineadas con los procedimientos definidos para la plataforma y sus áreas de soporte.
ALCANCE
Aplica para todos los agentes de SAC México encargados de atender solicitudes relacionadas con:
Errores de plataforma.
Problemas de autenticación.
Cambios de correo.
Integraciones.
Gestión de Wallet.
Información de órdenes.
Métodos de pago.
Comunidades.
Garantías.
Gestión de proveedores.
Configuración de usuarios.
DEFINICIONES
OTP
Código temporal de seguridad utilizado para validar la identidad del usuario durante procesos de autenticación.
Wallet
Billetera virtual disponible dentro de la plataforma para administrar saldos, pagos, ganancias y retiros.
Integración
Proceso mediante el cual una plataforma externa como Shopify se conecta con Dropi para sincronizar productos y órdenes.
Cambio de Correo
Proceso de actualización del correo de acceso y autenticación de un usuario mediante validación de identidad.
Comunidad
Grupo de usuarios afiliados a programas especiales que pueden acceder a beneficios específicos dentro de la plataforma.
Usuario Logístico
Usuario secundario creado dentro de una cuenta principal para apoyar procesos operativos y logísticos.
Pago Anticipado
Modalidad donde el cliente realiza el pago antes de que la orden sea procesada y despachada.
Pago Contra Entrega
Modalidad donde el cliente realiza el pago al momento de recibir el producto.
RESPONSABLES
GUIA DETALLADA
5.1 ERRORES DE PLATAFORMA
La atención de errores de plataforma tiene como objetivo identificar si la incidencia puede resolverse mediante validaciones básicas o si requiere escalamiento al área de Desarrollo.
5.1.1 No es posible guardar datos personales
Cuando el usuario indique que no puede guardar sus datos personales, se deben realizar validaciones relacionadas con el documento de identidad y las imágenes cargadas.
Procedimiento
Validar que las imágenes pesen menos de 2 MB.
Solicitar cambiar el nombre del archivo por uno corto.
Verificar que el documento tenga la cantidad correcta de caracteres.
Solicitar nuevamente el proceso.
Si el error continúa, solicitar evidencia y escalar a Desarrollo.
Consideraciones
INE: 13 cifras.
Pasaporte y NIT: 10 cifras.
CC: 13 cifras
5.1.2 Problemas con códigos OTP
Cuando el usuario no recibe los códigos OTP se debe validar primero el proveedor de correo electrónico utilizado.
Procedimiento
Verificar si utiliza Hotmail, Outlook o MSN.
Solicitar revisión de Spam.
Recomendar activación de 2FA.
Solicitar nuevo envío del código.
Validar si requiere cambio de correo.
Consideraciones
Los retrasos suelen presentarse en Hotmail, Outlook y MSN.
El sistema genera correctamente los códigos.
El problema depende del proveedor de correo.

Información requerida
Nombre completo.
Correo actual.

Documento de identidad.
Número celular.
Correo actual de acceso.
Nuevo correo.
Fotografías del documento.
Fotografías tipo selfie con documento.

Validar documentos.
Crear carpeta de evidencias.

Compartir enlace de reunión.

5.3 ESCALAMIENTO A DESARROLLO
Los casos relacionados con errores visuales o funcionalidades que no aparecen dentro de la plataforma deben ser transferidos directamente al área de Desarrollo.
Casos frecuentes
Botones que no aparecen.
Catálogo invisible.
Campos faltantes.
Errores visuales.
Problemas de interfaz.
Consideraciones
Siempre solicitar evidencia.
La evidencia debe acompañar el escalamiento.
5.4 INTEGRACIONES
Las solicitudes relacionadas con integraciones deben transferirse directamente a la bandeja de Integraciones.
Casos frecuentes
Órdenes no sincronizadas desde Shopify.
Diferencias de stock entre Shopify y Dropi.
Productos visibles en una plataforma y no en otra.
Generación de Tokens.
Chatea Pro.
Procedimiento
Identificar el tipo de integración.
Solicitar evidencia.
Transferir a Integraciones.
Registrar el caso.
5.5 ELIMINACIÓN E INACTIVACIÓN DE CUENTA
Actualmente no es posible eliminar una cuenta de manera definitiva desde la plataforma. Sin embargo, sí es posible solicitar la inactivación permanente de la cuenta mediante un proceso interno.
Procedimiento
Recibir la solicitud del usuario.
Validar que la cuenta no presente saldos negativos.
Informar al usuario las condiciones de la inactivación.
Solicitar confirmación para continuar con el proceso.
Escalar la solicitud al área correspondiente.
Informar los tiempos estimados de gestión.
Consideraciones
Una cuenta inactivada no podrá volver a utilizarse.
El proceso puede tardar aproximadamente 5 días hábiles.
No se debe gestionar la solicitud si existen saldos negativos.
5.6 RECARGAS DE WALLET
La Wallet permite al usuario administrar fondos para el procesamiento de órdenes, pago de fletes y demás operaciones disponibles dentro de la plataforma.
Procedimiento
Ingresar al panel de usuario.
Acceder al módulo Wallet.
Seleccionar la opción Recargar Saldo.
Elegir el método de pago disponible.
Registrar el valor a recargar.
Completar el proceso de pago.
Verificar la acreditación del saldo.
Consideraciones
El saldo reflejado podrá utilizarse para generar órdenes y cubrir costos operativos.
El usuario debe conservar el comprobante de pago.
Algunas pasarelas pueden presentar tiempos de validación.

Cuando un usuario solicite información sobre cómo funciona la plataforma, cómo comenzar a vender o cómo convertirse en proveedor, se debe orientar mediante los recursos de formación disponibles en Dropi Academy.
Procedimiento
Iniciar sesión en la plataforma.
Acceder al menú principal.
Seleccionar la opción Dropi Academy.
Consultar los cursos disponibles.
Realizar las capacitaciones recomendadas.
Beneficios
Formación para nuevos usuarios.
Estrategias de venta.
Configuración de tiendas.
Uso adecuado de la plataforma.
Consideraciones
Se recomienda iniciar con los cursos básicos.
El contenido puede actualizarse periódicamente.
5.8 TIEMPOS DE ENTREGA
Los tiempos de entrega dependen directamente de las transportadoras y de las condiciones logísticas de cada destino.
Procedimiento
Validar el estado actual de la guía.
Revisar la trazabilidad disponible.
Informar al usuario la información registrada.
Recomendar seguimiento constante de la guía.
Consideraciones
No existen tiempos fijos garantizados.
Los tiempos pueden variar por ubicación, demanda o condiciones climáticas.
No deben prometerse fechas exactas de entrega.
5.9 COSTOS DE ENVÍO
Los costos de envío son variables y dependen de factores logísticos asociados a cada pedido.
Factores que influyen
Ciudad de destino.
Distancia recorrida.
Peso del paquete.
Dimensiones del producto.
Transportadora asignada.
Consideraciones
No existen tarifas únicas para todos los pedidos.
Los costos pueden variar según la operación.
5.10 COBERTURAS
La cobertura logística depende de las zonas habilitadas por cada transportadora y de las condiciones operativas vigentes.
Procedimiento
Validar la ciudad o zona consultada.
Revisar la cobertura disponible.
Informar al usuario el resultado de la validación.
Consideraciones
Algunas zonas pueden presentar restricciones.
La cobertura puede variar según la transportadora.
5.11 BÚSQUEDA DE PRODUCTOS
La plataforma permite realizar búsquedas mediante ID de producto o utilizando imágenes de referencia.
Procedimiento
Ingresar al módulo Catálogo.
Utilizar el buscador disponible.
Buscar por ID de producto o imagen.
Revisar las alternativas disponibles.
Consideraciones
La búsqueda por imagen permite encontrar productos similares.
Es recomendable utilizar imágenes claras y completas.
5.12 RETIROS
Los retiros permiten transferir las ganancias disponibles desde la Wallet hacia los medios de pago habilitados.
Procedimiento
Acceder al módulo Wallet.
Seleccionar la opción de retiro.
Elegir la pasarela correspondiente.
Registrar la información requerida.
Confirmar la solicitud.
Consideraciones
Los procedimientos específicos se encuentran en los instructivos oficiales.
El usuario debe verificar previamente la información registrada.
5.13 CONTACTO CON PROVEEDORES
La plataforma permite consultar información de contacto de los proveedores directamente desde el catálogo de productos.
Procedimiento
Ingresar al catálogo.
Seleccionar el producto.
Dar clic sobre el nombre del proveedor.
Consultar la información disponible.
Iniciar conversación cuando sea necesario.
Consideraciones
La información disponible dependerá de cada proveedor.
La comunicación puede realizarse directamente desde la plataforma.
5.14 FILTRADO DE ÓRDENES
La funcionalidad de filtros permite localizar órdenes específicas según fechas o estados.
Uso de filtros dentro del módulo Mis Órdenes.
Procedimiento
Ingresar al módulo Mis Órdenes.
Seleccionar la opción Filtros.
Definir el rango de fechas.
Seleccionar el estado de la orden.
Aplicar los filtros.
Consultar los resultados.
Consideraciones
Es posible consultar órdenes de hasta tres meses atrás.
Los filtros facilitan la búsqueda de pedidos específicos.
5.15 MÉTODOS DE PAGO
La plataforma dispone de dos modalidades principales para la gestión de pagos de pedidos: Pago Anticipado y Pago Contra Entrega. Cada modalidad tiene características específicas relacionadas con el recaudo y procesamiento de órdenes.
Explicación de los métodos de pago disponibles dentro de la plataforma.
Consideraciones
El método de pago impacta directamente la gestión financiera de la orden.
El usuario debe conocer las diferencias entre ambas modalidades antes de generar pedidos.
Los costos de producto y envío se gestionan de forma distinta según el tipo de pago.
5.16 PAGO ANTICIPADO
En esta modalidad, el cliente final realiza el pago antes de que la orden sea procesada dentro de Dropi. El dinero es recibido directamente por el Dropshipper mediante su pasarela de pago o tienda virtual.
Flujo del proceso
El cliente realiza el pago.
El Dropshipper recibe el dinero.
La orden es creada o sincronizada en Dropi.
El costo del producto y envío se descuenta de la Wallet.
Se genera la guía.
Se realiza el despacho.
El pedido es entregado al cliente final.
Consideraciones
El dinero no es administrado por Dropi.
El usuario es responsable de la gestión del pago recibido.
La Wallet debe contar con saldo suficiente para procesar la orden.
5.17 PAGO CONTRA ENTREGA
En esta modalidad el cliente realiza el pago al momento de recibir el producto. Sin embargo, el costo inicial del envío es descontado temporalmente de la Wallet del usuario.
Flujo del proceso
Se genera la orden.
Se descuenta inicialmente el costo del envío.
La transportadora realiza la entrega.
El cliente realiza el pago.
Se reintegra el valor correspondiente al envío.
Consideraciones
El costo del envío se descuenta inicialmente para cubrir la operación logística.
Si la orden es entregada, el valor correspondiente se reintegra.
Las devoluciones no generan ganancias para el Dropshipper.
5.18 DEVOLUCIONES Y GANANCIAS
Las ganancias únicamente se generan sobre órdenes efectivamente entregadas al cliente final. Las devoluciones no generan liquidación de utilidades.
Gestión de devoluciones
Las transportadoras normalmente realizan dos intentos de entrega.
Si la entrega no se concreta, el pedido es devuelto al proveedor.
No se generan costos adicionales para el Dropshipper asociados a la devolución del producto.
Liquidación de ganancias
Las ganancias son liquidadas diariamente por la plataforma y pueden consultarse desde el Historial de Cartera.
Consideraciones
Solo se liquidan órdenes entregadas.
Las devoluciones no generan utilidad.
La información puede consultarse desde la Wallet.
5.19 DESCUENTO DE SALDO EN WALLET
Cuando un usuario consulta por qué se descuenta saldo de su Wallet para generar órdenes, se debe validar inicialmente si pertenece a una comunidad con beneficios especiales.
Procedimiento
Verificar si el usuario pertenece a una comunidad.
Validar si tiene habilitado el beneficio de despacho sin saldo.
Si corresponde, solicitar activación mediante JIRA.
Si no pertenece a una comunidad, explicar el funcionamiento de la Wallet.
Consideraciones
El descuento inicial permite cubrir costos operativos y logísticos.
Algunas comunidades cuentan con beneficios especiales.
Las órdenes sin recaudo utilizan el saldo disponible en Wallet.
5.20 LINK DE AFILIADO
Los usuarios pueden compartir enlaces de afiliación para invitar nuevos registros a la plataforma.
Procedimiento
Ingresar a Configuración de Tienda.
Localizar el enlace de afiliado.
Copiar el enlace.
Compartirlo con los usuarios que desea referir.
Consideraciones
Cada usuario cuenta con un enlace único.
El enlace debe compartirse directamente desde la plataforma.
5.21 USUARIO LOGÍSTICO
El usuario logístico es una cuenta secundaria creada bajo una cuenta principal para apoyar procesos operativos y de gestión.
Procedimiento
Acceder a la configuración de usuarios.
Crear un nuevo usuario.
Asignar permisos según corresponda.
Guardar la configuración.
Consideraciones
Los permisos deben asignarse según la función del usuario.
La cuenta principal mantiene el control administrativo.
5.22 GESTIÓN DE COMUNIDADES
Las comunidades permiten acceder a beneficios y programas específicos definidos por la plataforma
5.22.1 Cambio de Comunidad
Cuando un usuario solicite cambiar de comunidad, deberá realizar la gestión mediante la herramienta oficial definida por la plataforma.
Procedimiento
Ingresar al aplicativo oficial.
Registrar la información solicitada.
Enviar la solicitud.
Esperar la validación interna.
Recibir la confirmación por correo electrónico.
Consideraciones
Las solicitudes por correo ya no son procesadas.
El usuario debe utilizar el correo asociado a su cuenta.
5.22.2 Creación de Comunidad
Cuando un usuario desee crear una comunidad, deberá consultar los requisitos establecidos en la documentación oficial de soporte.
Consideraciones
Debe cumplir los requisitos definidos por la plataforma.
La solicitud será validada internamente.
5.22.3 Beneficio de Despacho sin Saldo
Los usuarios pertenecientes a determinadas comunidades pueden acceder al beneficio de despacho sin saldo disponible en Wallet.
Procedimiento
Verificar la comunidad del usuario.
Confirmar si el beneficio está activo.
Solicitar activación mediante JIRA cuando corresponda.

5.24 GARANTÍAS
Las garantías permiten reportar inconformidades relacionadas con productos entregados al cliente final.
Requisitos
La guía debe encontrarse en estado Entregado.
El reporte debe realizarse dentro de los 10 días posteriores a la entrega.
Procedimiento
Validar el estado de la guía.
Confirmar que se encuentre entregada.
Ingresar al módulo de Garantías.
Registrar la solicitud.
Adjuntar las evidencias correspondientes.
Realizar seguimiento al caso.
Consideraciones
Las garantías no deben gestionarse por fuera del módulo establecido.
La información debe ser completa y verificable.
Los tiempos de reporte son obligatorios.
