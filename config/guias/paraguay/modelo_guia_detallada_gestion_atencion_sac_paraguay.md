# Modelo Guía Detallada Gestión Atención SAC PARAGUAY

OBJETIVO
Establecer los lineamientos para la atención, orientación y gestión de las consultas recibidas por los usuarios de la operación Paraguay, garantizando respuestas homogéneas, oportunas y alineadas con los procedimientos definidos para cada área de atención.
ALCANCE
Aplica para todos los agentes encargados de la atención de usuarios de la operación Paraguay y contempla la gestión de solicitudes relacionadas con:
Triage.
Comercial.
Administrativo.
Logística.
Garantías.
Soporte Técnico.
Incluye la atención de consultas operativas, comerciales, financieras, logísticas y técnicas relacionadas con el uso de la plataforma y la gestión de pedidos.
DEFINICIONES
Dropshipper
Usuario que comercializa productos publicados dentro de la plataforma sin necesidad de contar con inventario propio, gestionando las ventas mientras el proveedor realiza el despacho correspondiente.
Guía
Documento logístico generado para realizar el seguimiento y transporte de una orden desde el proveedor hasta el cliente final.
Novedad
Situación presentada durante el proceso logístico que requiere una acción correctiva por parte del usuario, la transportadora o el equipo de soporte.
Garantía
Proceso mediante el cual se reporta una inconformidad relacionada con un producto recibido por el cliente final para su respectiva validación.
Recarga
Proceso mediante el cual el usuario adiciona saldo a su Wallet para realizar operaciones dentro de la plataforma.
Retiro
Solicitud realizada por el usuario para transferir los fondos disponibles en su Wallet a una cuenta bancaria registrada.
Comunidad
Grupo de usuarios afiliados a programas especiales que pueden acceder a beneficios adicionales definidos por la plataforma.
RESPONSABLES
GUIA DETALLADA
5.1 INICIO DE JORNADA
La jornada inicia con el envío del reporte de apertura de las bandejas activas utilizando la plantilla definida para la operación Paraguay. Este reporte permite visualizar la carga operativa y distribuir adecuadamente la gestión del día.
Procedimiento
Ingresar a la plataforma de gestión.
Validar el estado de las bandejas activas.
Contabilizar los casos pendientes por categoría.
Diligenciar la plantilla de inicio.
Compartir el reporte con el equipo correspondiente.
Categorías reportadas
Triage.
Comercial.
Administrativo.
Logística.
Garantías.
Soporte Técnico.
Total general.
5.2 CIERRE DE JORNADA
Al finalizar la jornada se debe reportar el estado final de las bandejas activas, informando la cantidad de casos pendientes y las novedades relevantes para el siguiente turno.
Procedimiento
Revisar los casos pendientes.
Consolidar la información por categoría.
Diligenciar la plantilla de cierre.
Compartir el reporte al equipo.
5.3 GESTIÓN DE TRIAGE
La bandeja de Triage tiene como objetivo brindar orientación inicial a los usuarios y gestionar consultas frecuentes relacionadas con el uso de la plataforma, seguimiento de órdenes y procesos operativos.
5.3.1 Primeras Ventas en Dropi
Cuando un usuario indica que es su primera vez utilizando la plataforma, se le debe orientar para que realice los cursos disponibles en Dropi Academy, permitiéndole conocer las funcionalidades básicas y el proceso de venta.
Procedimiento
Ingresar al módulo de novedades.
Buscar la orden o guía correspondiente.
Seleccionar la opción "Solucionar".
Seguir las instrucciones mostradas por la plataforma.
5.3.4 Consulta de Tiempos de Entrega
No se deben prometer fechas exactas de entrega, ya que las transportadoras manejan su propia programación de rutas y pueden presentarse novedades operativas.
Se debe recomendar al usuario realizar seguimiento constante a la guía y estar atento a las comunicaciones realizadas por la transportadora.
5.3.5 Consulta de Pedidos Antiguos
Cuando un usuario no encuentra una orden en la plataforma, se debe validar si la consulta corresponde a pedidos antiguos.
Procedimiento
Ingresar al módulo Mis Pedidos.
Seleccionar la opción de filtros.
Configurar el rango de fechas requerido.
Aplicar los filtros para visualizar órdenes antiguas.
5.3.6 Guías No Entregadas
Cuando una guía aparece como "No Entregada", se debe validar si la transportadora intentó contactar al cliente final.
Generalmente estos casos corresponden a intentos fallidos de contacto y posteriormente se programa una nueva visita o gestión de entrega
5.3.7 Órdenes Pendientes de Despacho
Los proveedores cuentan con hasta 72 horas para generar la guía y realizar el despacho correspondiente.
Antes de escalar un caso, se debe validar que el tiempo establecido haya sido superado.
5.3.8 Anulación de Guías con Movimiento
Las guías únicamente pueden ser anuladas directamente cuando se encuentran en estado pendiente o guía generada.
Cuando una guía ya presenta movimiento logístico, únicamente podrá solicitarse la devolución del pedido, aplicando las condiciones definidas para el cobro del flete.
5.3.9 Pedidos de Muestra
Los pedidos de muestra permiten al Dropshipper conocer el producto antes de comercializarlo.
Estos pedidos se generan sin recaudo, ya que corresponden a compras realizadas directamente por el Dropshipper y no por un cliente final.
5.3.10 Ganancias de Órdenes Entregadas
Las ganancias de órdenes con recaudo se reflejan una vez la orden se encuentre en estado Entregado y se realicen los procesos internos de actualización.
En órdenes sin recaudo, el cliente final ya debió haber realizado el pago directamente al Dropshipper antes de la creación de la orden
5.3.11 Comunidades y Beneficios
Los usuarios pueden solicitar el ingreso a comunidades para acceder a beneficios definidos por la plataforma.
Procedimiento
Ingresar a la herramienta de solicitud.
Registrar los datos solicitados.
Enviar la solicitud.
Esperar la validación interna.
Recibir confirmación por correo electrónico.
5.3.12 FACTURACIÓN
Cuando un Dropshipper solicita una factura relacionada con una compra realizada dentro de la plataforma, se debe validar el tipo de factura requerida y orientar al usuario sobre el responsable de su emisión.
Procedimiento
Identificar el tipo de compra realizada.
Validar si la consulta corresponde a productos o fletes.
Informar al usuario el responsable de la facturación.
Orientar sobre el canal correspondiente para solicitar la factura.
Consideraciones
Dropi únicamente genera facturas correspondientes a los fletes.
Las facturas de los productos son emitidas directamente por el proveedor.
Cuando el usuario requiera la factura del producto deberá comunicarse directamente con el proveedor correspondiente.
Se debe brindar orientación clara para evitar solicitudes dirigidas al área incorrecta.
5.3.13 CAMBIO DE CORREO
El cambio de correo es un procedimiento de seguridad mediante el cual se actualiza la dirección electrónica asociada a una cuenta cuando el usuario pierde acceso a su correo actual o requiere modificarlo.
Información requerida
Para iniciar la solicitud se debe solicitar al usuario:
Nombre completo.
Correo de usuario actual.
País.
Número de documento de identidad.
Número celular.
Correo electrónico que desea modificar.
Nuevo correo electrónico.
Fotografía del documento de identidad (frente y reverso).
Fotografía tipo selfie sosteniendo el documento de identidad visible.
Procedimiento
Recibir la solicitud.
Validar que el usuario suministre toda la información requerida.
Revisar que las evidencias sean legibles.
Registrar la solicitud en el documento de control correspondiente.
Coordinar la validación de identidad.
Informar al usuario la fecha y hora de la validación.
Confirmar la actualización una vez finalizado el proceso.
Consideraciones
No deben realizarse cambios sin validación previa de identidad.
Las fotografías deben ser legibles y permitir verificar claramente la información.
Toda solicitud debe quedar registrada para fines de trazabilidad y auditoría.
5.4 GESTIÓN COMERCIAL
La gestión comercial contempla solicitudes relacionadas con anulaciones de pedidos, validación de evidencias y aprobación de productos por parte de los proveedores.
5.4.1 ANULACIÓN DE GUÍAS SOLICITADAS POR DROPSHIPPERS
Cuando un Dropshipper solicita la anulación de una guía, es necesario validar la evidencia correspondiente antes de escalar la solicitud al área encargada.
Información requerida
Número de guía.
Estado actual de la guía.
Motivo detallado de la cancelación.
Nombre del proveedor.
Evidencia de conversación con el proveedor.
Nombre del Dropshipper solicitante.
Procedimiento
Recibir la solicitud.
Validar que la evidencia se encuentre completa.
Confirmar que el nombre de contacto coincida con el registrado en la plataforma.
Verificar que la guía sea visible dentro de la evidencia suministrada.
Escalar la solicitud al área correspondiente.
Informar al usuario el estado de la gestión.
Solicitudes de indemnización
Cuando el Dropshipper solicite una indemnización, se deberá realizar una validación adicional para determinar si aplica.
Consideraciones
La evidencia debe encontrarse completa antes de escalar el caso.
Toda solicitud debe quedar registrada.
Las indemnizaciones tienen un tiempo estimado de validación entre 30 y 45 días hábiles.
5.4.2 ANULACIÓN DE GUÍAS SOLICITADAS POR PROVEEDORES
Cuando la solicitud de anulación sea realizada por un proveedor, se deberá validar que el Dropshipper se encuentre informado o haya solicitado la cancelación.
Procedimiento
Solicitar evidencia de la conversación.
Validar que el Dropshipper tenga conocimiento de la anulación.
Verificar la información registrada en la plataforma.
Escalar la solicitud al área encargada.
Consideraciones
No deben gestionarse anulaciones sin evidencia.
La información suministrada debe coincidir con los registros de la plataforma.
5.4.3 APROBACIÓN DE PRODUCTOS
La aprobación de productos corresponde al proceso mediante el cual se valida que los artículos publicados por los proveedores cumplan los requisitos mínimos establecidos para su comercialización.
Requisitos de aprobación
Stock igual o superior a 100 unidades.
Descripción detallada del producto.
Mínimo tres imágenes.
Imagen principal o de portada.
Procedimiento
Revisar la información del producto.
Validar que cumpla todos los requisitos.
Identificar posibles inconsistencias.
Solicitar correcciones cuando sea necesario.
Escalar la solicitud para aprobación.
Consideraciones
Los productos incompletos no deben aprobarse.
El proveedor debe realizar las correcciones antes de una nueva revisión.
5.5 GESTIÓN ADMINISTRATIVA
La gestión administrativa comprende las consultas relacionadas con retiros de saldo, recargas de Wallet y movimientos financieros dentro de la plataforma.
5.5.1 RETIROS DE SALDO
Los retiros permiten transferir los fondos disponibles de la Wallet hacia una cuenta bancaria previamente registrada.
Procedimiento
Ingresar al módulo Configuraciones.
Registrar los datos bancarios.
Acceder a la opción Retiros de Saldo.
Registrar la solicitud.
Confirmar la operación.
Tiempos de procesamiento
Solicitudes realizadas antes de las 10:00 a.m.: procesadas el mismo día hábil.
Solicitudes posteriores a las 10:00 a.m.: procesadas el siguiente día hábil.
Acreditación estimada: entre 24 y 48 horas hábiles.
Consideraciones
Los retiros internacionales deben gestionarse siguiendo las instrucciones indicadas para otros países.
El usuario debe conservar el comprobante de la solicitud.
5.5.2 RECARGAS
Las recargas permiten adicionar saldo a la Wallet para realizar operaciones dentro de la plataforma.
Procedimiento
Ingresar al módulo Historial de Cartera.
Seleccionar la opción de recarga.
Elegir la pasarela disponible.
Registrar la información requerida.
Confirmar la transacción.
Consideraciones
Las recargas únicamente pueden realizarse mediante las pasarelas habilitadas.
Los tiempos de acreditación son de 24 a 48 horas hábiles.
Si la recarga no se refleja después del tiempo establecido, el caso deberá escalarse para revisión.
5.6 GESTIÓN LOGÍSTICA
La gestión logística comprende las solicitudes relacionadas con actualizaciones de estado, devoluciones, novedades de transporte y guías sin movimiento. Su objetivo es garantizar el seguimiento oportuno de los pedidos y brindar visibilidad al usuario sobre el estado de sus envíos
5.6.1 ACTUALIZACIÓN DE ESTATUS
Cuando una guía ya fue entregada pero el estado no se ha actualizado en la plataforma, se debe validar la evidencia correspondiente antes de escalar el caso.
Evidencias requeridas
Fotografía del producto recibido.
Fotografía de la guía adherida al paquete.
Evidencia de conversación con el cliente cuando aplique.
Procedimiento
Recibir la solicitud.
Solicitar las evidencias requeridas.
Validar que las imágenes sean legibles.
Confirmar que la información corresponda a la guía reportada.
Escalar al área de Actualización de Estatus.
Informar al usuario sobre el proceso realizado.
Consideraciones
No deben escalarse casos sin evidencia.
La información suministrada debe permitir validar la entrega realizada.
Toda gestión debe quedar registrada.
5.6.2 DEVOLUCIÓN INJUSTIFICADA
Cuando una guía entra en devolución y el usuario manifiesta desconocer el motivo, se debe validar el historial de intentos de entrega realizados por la transportadora.
Procedimiento
Solicitar el número de guía.
Verificar el historial logístico.
Validar la cantidad de intentos de entrega realizados.
Informar al usuario el resultado de la validación.
Consideraciones
Las transportadoras realizan múltiples intentos de entrega antes de generar una devolución.
El estado debe validarse directamente en la plataforma.
La información suministrada debe ser clara y verificable.
5.6.3 GUÍA SIN MOVIMIENTO
Las guías sin movimiento corresponden a órdenes que no presentan actualizaciones logísticas durante un período prolongado de tiempo.
Procedimiento
Solicitar el número de orden o guía.
Verificar la fecha del último movimiento registrado.
Confirmar si han transcurrido más de 72 horas sin actualización.
Escalar el caso cuando corresponda.
Realizar seguimiento hasta obtener respuesta.
Consideraciones
Solo deben escalarse casos que superen las 72 horas sin movimiento.
El usuario debe recibir información clara sobre el estado del caso.
Toda gestión debe registrarse para trazabilidad.
5.7 GESTIÓN DE GARANTÍAS
La gestión de garantías permite atender las inconformidades reportadas por los usuarios respecto a productos recibidos, garantizando la validación de las evidencias y el cumplimiento de las políticas establecidas.
5.7.1 REPORTE DE GARANTÍAS
Para que una garantía pueda ser gestionada, es indispensable que el producto haya sido recibido por el cliente final.
Procedimiento
Verificar que la orden se encuentre entregada.
Solicitar el número de orden o guía.
Validar la información suministrada.
Escalar el caso al área correspondiente.
Realizar seguimiento hasta obtener respuesta.
Consideraciones
No es posible gestionar garantías sobre pedidos no entregados.
Las evidencias son obligatorias para la validación del caso.
Toda solicitud debe registrarse.
5.7.2 GARANTÍAS SIN MOVIMIENTO
Cuando una garantía ya fue reportada y no presenta avances, se debe validar el número de orden o guía y remitir el caso para revisión.
Procedimiento
Solicitar el número de orden o guía.
Confirmar que la solicitud corresponda a una garantía.
Revisar el estado actual del proceso.
Escalar el caso para seguimiento.
Informar al usuario el estado de la gestión.
Consideraciones
Siempre debe solicitarse el número de orden o guía.
Las consultas deben dirigirse a la bandeja correspondiente.
Toda gestión debe quedar documentada.
5.8 SOPORTE TÉCNICO
La gestión de soporte técnico comprende solicitudes relacionadas con integraciones, errores de plataforma, autenticación y problemas de acceso reportados por los usuarios.
5.8.1 INTEGRACIONES
Las solicitudes relacionadas con Shopify, Dropify, Emidica, Tokens u otras integraciones deben ser remitidas al equipo especializado.
Casos frecuentes
Integración con Shopify.
Integración con Dropify.
Integración con Emidica.
Problemas relacionados con Tokens.
Errores de sincronización.
Consideraciones
No deben realizarse configuraciones manuales desde SAC.
Toda solicitud debe ser asignada a la bandeja de Integraciones.
5.8.2 ERRORES DE DESARROLLO
Cuando un usuario reporta errores de tipo técnico, como errores 500, se deben realizar validaciones básicas antes de escalar el caso.
Procedimiento
Solicitar al usuario borrar caché y cookies.
Solicitar cierre e inicio de sesión nuevamente.
Recomendar el uso de un computador para la validación.
Verificar si el error continúa.
Solicitar evidencia fotográfica.
Escalar al área de Desarrollo cuando sea necesario.
Consideraciones
Las validaciones iniciales son obligatorias antes de escalar.
La evidencia debe mostrar claramente el error presentado.
Toda gestión debe registrarse.
5.8.3 PROBLEMAS CON CÓDIGOS DE VERIFICACIÓN
Algunos usuarios pueden presentar inconvenientes para recibir códigos de autenticación enviados por correo electrónico.
Procedimiento
Validar el proveedor de correo utilizado.
Confirmar que el usuario tenga habilitada la autenticación correspondiente.
Solicitar una nueva generación del código.
Verificar si el problema persiste.
Escalar el caso cuando sea necesario.
Consideraciones
Los problemas suelen presentarse principalmente con cuentas Hotmail, Outlook y MSN.
Se recomienda activar el sistema de autenticación de dos factores.
Si el inconveniente continúa, el caso deberá ser remitido al área de Desarrollo.
